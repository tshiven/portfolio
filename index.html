Mar 2026 — nowStarAI Lab
UCLA

Caching an exact random variate generator

A memoization layer over the Saad–Lee exact sampler: up to 59× faster, byte-identical output, and exactly the same random bits consumed.

C · cache design · bit-level manipulation · benchmarking

  • Exact samplers guarantee the distribution you asked for, but pay for it with up to 64 CDF evaluations per sample. I built rvg_cache, an add-on layer that removes most of that cost while leaving the original librvg source completely unmodified.
  • Two caches with different jobs: a 65,536-slot open-addressed head cache with a bounded six-slot probe window — no resizing, no eviction, so memory is fixed and the worst-case lookup cost is constant — plus a tail cache keyed on the full sampler state after the final coin flip, which skips the deterministic remainder of a walk entirely.
  • Discrete distributions run 33× to 59.5× faster at 100,000 samples; continuous distributions gain 1.34× to 1.47×. The gap is structural, and the write-up explains why.
  • Correctness came before speed. Every result was checked against unmodified librvg on both the raw bit pattern and the exact coin-flip count, across 33 parameterisations at 20,000 seeds each: zero mismatches, zero leaked bytes. Flip-count matching is the strict test — a broken cache desynchronises the random stream long before any distributional test would notice.
  • Cached values are stored and compared as raw bit patterns, never as floats, so -0.0 and NaN key as distinct entries instead of silently colliding.
  • Documented the limits as carefully as the wins: single-threaded only, a 64-CDF cap, and results from one machine and one compiler.

Fixed-size tables, no dynamic growth, a bounded worst case, and an automatic fallback to the uncached path — the same constraints I want to design under on an MCU.
